PLATFORM

The model should not own your architecture.

Every tool call routes through an approval boundary. Switch between local llama.cpp, Claude, or GPT while preserving the same 118 annotated tools, Ghost DB traces, and policy gates.

Providers are plug-ins

Local llama.cpp first, cloud APIs when you allow it. One runtime config swaps inference without touching agent logic or memory.

Governed by default

Safety tiers on every tool: read-only runs free, writes confirm once per stage, destructive ops gate hard. Staged approvals, one prompt per session.

Memory that persists

Ghost DB keeps six memory types — episodic, semantic, procedural — with hybrid BM25 + vector retrieval and nightly autoMimpi consolidation.

GHOST DB

Six memory types. One retrieval path.

Memories are typed at write time and fused at read time — hybrid BM25 + vector (HNSW, cosine) returns ranked hits with per-result confidence. The nightly autoMimpi daemon decays, prunes, and consolidates.

Semantic

UNDER THE HOOD

What actually happens on a tool call.

No magic — a deterministic pipeline. Every request your IDE sends walks the same six steps, and each one is observable in the metrics resource.

1IDE dispatch

Your client sends a JSON-RPC tools/call over stdio or streamable-HTTP. Auth first: X-API-Key compared timing-safe.

2Allowlist + tier

JEBAT_MCP_TOOLS_ALLOW filters the registry; the tool's declared safety_tier decides the next move — auto, confirm, or refuse.

3Approval gate

confirm/dangerous calls return approval_required with the exact arguments — approve in the CLI, retry. Nothing executes silently.

4Deadline dispatch

The call runs under its declared timeout (async, thread-offloaded where the OS blocks). Hung tools die at the deadline with a structured isError.

5Progress + result

Long tools stream notifications/progress (agent loop iterations report fractional progress). Results cap at size limits; full output spills to jebat://artifact.

6Metrics recorded

Call count, error count, and latency land in per-tool rings — query live via resources/read: jebat://metrics/tools.

The install script provisions Python, a venv, the jebat launcher, and the MCP entrypoint — no sudo, everything in ~/.local. 118 tools register on connect; write-tier tools stop at your approval gate.

When to pick stdio

Fastest path, no network hop, process lifetime tied to the IDE. Best for single-dev workstations. Requires the venv on the same machine as the IDE.

When to pick ide-config

You already have JEBAT installed and just want the JSON. jebat mcp ide-config prints vendor-exact shapes — VS Code wants mcp.servers, Cursor wants mcpServers; hand-editing gets this wrong.

When to pick Docker

Isolation and pinning: the container freezes its own deps, the healthcheck uses a finite TCP probe because GET /mcp is long-lived SSE. Costs a network hop to the IDE via docker exec.

When to pick npx

No clone, no repo checkout — the launcher downloads and bootstraps Python on first run. Slightly slower first start; afterwards identical to CLI. Great for trying JEBAT before committing.

When to pick Remote HTTP

One server, many clients: teammates share a key-gated bus behind TLS. The API key is mandatory — the transport rejects unauthenticated calls with a timing-safe compare. Stateless: no sticky sessions needed.

MODEL ROUTING

Providers are a routing table, not an architecture decision.

Every provider implements one interface; the router tries them in priority order and your tools, memory, and approvals are untouched by the switch.

Failover chain

generate_with_failover() walks providers in configured order. Local llama.cpp answers first; cloud keys only fire when you let them — and per-route policy gates apply to either.

Adaptive context budget

Input is budgeted against the model's real context window (input_token_budget()) — prompts are truncated to tokens, not characters, so a 4k local model and a 128k cloud model both get valid input.

NineRouter integration

Already running a local LLM proxy? JEBAT speaks ninerouter:// natively — point it at your existing gateway and keep one endpoint for every model.

Per-call cost visibility

Token usage is recorded per provider and per call (token_usage.py) — the WebUI surfaces spend, and local routes report cost as unmetered instead of hiding it.

RETRIEVAL

How a memory query actually resolves.

Implemented in EnhancedMemorySystem.retrieve() — every filter, weight, and fallback below is in the shipped code, not aspirational.

QUERY PIPELINE
1
Filter, before scoring

Candidates must pass every gate first: memory type, minimum strength, tag intersection, context match, time range. Cheap filters run before any embedding work.

2
Ghost DB vector search

If Ghost DB + embeddings are configured, the query embeds once and HNSW-indexed similarity (cosine) pulls top-K × 3 candidates. No Ghost DB? N-gram text similarity takes over — degraded, never broken.

3
Weighted score

Vector path: similarity×0.6 + strength×0.3 + activation×0.1. N-gram path: strength×0.6 + activation×0.3 + similarity×0.1 — recency and usage dominate when embeddings are unavailable.

4
Linked traces ride along

Results pull their linked traces (include_linked) so a decision arrives with its evidence — one query, full context chain.

5
Bounded injection

Recalled context enters the prompt under the same token budget as your task. Memory enriches; it never crowds out.

STRENGTH: EBBINGHAUS, NOT COUNTS
strength(t) = strength₀ · e−decay·Δt · (1 + reinforcement·0.5) reinforcement = min(1, access_count·0.1 + consolidation_count·0.2)

Memories follow a modified Ebbinghaus forgetting curve. Access frequency and consolidation events raise the reinforcement factor, slowing decay — a memory you keep using survives, one you ignore fades below the 0.3 floor and drops out of retrieval entirely.

The flip is deliberate: raw text similarity is noisy, so the fallback leans on proven trust (strength) and recent usefulness (activation) instead of pretending substring match means relevance.

automimpi consolidates nightly: traces are re-scored, decayed, pruned, and recurring error→fix pairs are promoted to Pattern memory — the retrieval stack gets smarter while you sleep, not while you wait.
