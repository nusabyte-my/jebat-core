## 1. ISF (Commercial or Industrial) charged on 0 sf — FIXED

Reported on study 99 "Sg. Lallang Semenyih - Industrial (Keith Khor)" (owner alandconsultingresearch@gmail.com): 27 units × 11,000 sf = **297,000 sf** total GFA, but B2 "Tabung ISF (Commercial or Industrial)" showed 0 sqft → RM 0 instead of 0.50 × 297,000 = RM 148,500.

Cause: the study's single unit type was stored `category: "residential"` (name said "Industrial(medium) Semi-D", 80×120 lot). The engine charges ISF commercial on every category that is NOT residential, so the whole 297,000 sf sat in the residential bucket — where `isfResidentialPerUnit` was 0.

Two shipped changes:
- **Unit category is now editable per-row** in the Apportionment table. It drives ISF residential vs commercial plus per-typology water/electricity, but was unreachable: the live table only exposed `%`, name, lot w/d — and `LandedMixTable` (the only table with a category control) is dead code, mounted nowhere.
- **One shared classifier**: `RESIDENTIAL_ISF_CATEGORIES` exported from `shared/feasibility/engine/statutory.ts`, replacing three separate hand-written lists (statutory.ts, index.ts, B2Statutory.tsx). B2 had been filtering `retail | industrial | industrial_terrace` while the engine charged "anything not residential" — displayed GFA could disagree with charged GFA.

Verified: totalGFA 297,000, chargeable 297,000, ISF commercial RM 148,500, basis "RM 0.50 psf × 297,000 sf commercial".

**Production data patch**: study 99's row category `residential` → `industrial` via guarded `jsonb_set` (only if old value was residential). Backup in `_backup_study99_inputs`. Committed as `031edb6`.

## 2. Reference Library — edit/delete now admin-only

Any logged-in account could edit/delete shared library content (categories + documents), because all KB mutations used `protectedProcedure`, which only proves existence of a session. Deleting a category unlinks its documents; deleting a document cascades its RAG chunks — one stray click strips the statutory library for everyone.

`categories.update`, `categories.delete`, `documents.delete` → `adminProcedure` (FORBIDDEN otherwise). UI hides Edit/Remove icons on category rows, the document delete button, and the "Add Category" header action for non-admins.

## 4. Lot Explorer snapshot — loading card baked into the PNG

The embedded explorer posts `aland-explorer-ready` from `Embed.ready()` at script boot, **before its first map tiles paint**. `screenshot()` called `__mylot_capture()` exactly once and, on null, fell through to `captureElement(mapAreaRef)` — a DOM capture of the whole card including the z-10 "Loading Lot Explorer…" overlay. Users got a loading screen instead of the map.

Fix: poll `iframe.contentWindow.__mylot_capture()` up to 6s at 150ms (it returns null until tiles paint, and it composites tiles + lot geometry so it can never contain the host overlay). If it never produces one, toast "Map is still loading — try the snapshot again in a moment." MyLot (cross-origin JUPEM iframe) and plain Leaflet keep the DOM-capture path.

## Corrections / gotchas
- Apportionment row `name` is free text while `category` drives statutory maths — names lie. Always check `unitTypes[].category`, never the name.
- `LandedMixTable` and `RiskFlagsPanel` and `AIAgentPanel` are dead code (mounted nowhere). Don't fix bugs there and expect users to see them.
- `buildBucket` filters `lines.filter(l => l.amount !== 0)` — a zero-amount statutory line disappears from `bucket.lines` entirely, so B2's `getAmt` returns 0 via `?? 0`, and a test must assert the rendered row rather than the line.
- Browser automation on `/calc` wedges the tab: the calc page holds a live SSE/poll connection so the tab never reaches "load complete". Open with `wait_until: "domcontentloaded"`, and never `tab.run("string")` with a statement — use `tab.evaluate("expression")`.
- Demo login for local verification: `GET /api/auth/demo-preset/user` with `credentials: 'include'` (dev only, `ENV.allowDemoLogin`). The `user@demo.aland` preset owns no studies by default — create one via `studies.create` (requires `inputsJson` as a string).
