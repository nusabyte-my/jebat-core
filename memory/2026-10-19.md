## 1. Database Architecture Separation (Zero Shared Resources)
- **Problem**: Baan Iyara was previously sharing the Erawan PostgreSQL container (`erawanqpos-postgres-1`, port 5433) with username `erawan`, and Redis on index 1, violating strict multi-tenant isolation.
- **Fixes**:
  - Provisioned dedicated Docker services `baaniyara-postgres` (`127.0.0.1:5435->5432`) and `baaniyara-redis` (`127.0.0.1:6381->6379`) with timezone `Asia/Bangkok`.
  - Dumped and restored `baaniyara_qsys` with 100% table and row parity (37 tables, 30 foreign keys, 104 indexes).
  - Executed `VACUUM (ANALYZE, VERBOSE)` and `REINDEX DATABASE baaniyara_qsys`.
  - Safely dropped residual `baaniyara_qsys` from Erawan's PostgreSQL container (`erawanqpos-postgres-1:5433`).
  - Fixed Postgres check constraints `chk_till_session_branch` and `chk_till_settlement_branch` to include `'baan-iyara'` (resolving Error 23514 on morning till auto-open).

## 2. Walk-in / POS Cart Past-Time Refusal Exemption
- **Problem**: Walk-in items added to cart at e.g. 11:13 and checked out at 11:22 were rejected by `bookings.service.ts` with `Cannot book a time that has already passed. Preferred time 11:13 is before the current time 11:22 MYT.`
- **Fix**: Exempted walk-ins and POS checkouts (`source === "walk_in" || autoAssignOnConvert === true`) from past-time checks, allowing in-cart floor sessions to check out cleanly regardless of elapsed time.

## 3. Daily Queue Branch Resolution & 10:00 AM Auto-Fallback
- **Problem**: Morning queue setup omitted `branchId` (saving as `NULL`), causing branch-scoped POS queries (`/queue/daily-order?branchId=baan-iyara`) to return empty `[]` and hard-block checkout.
- **Fixes**:
  - `setDailyOrder` and `autoSeedFromPreviousDay` automatically resolve `branchId` to `'baan-iyara'` if omitted.
  - `getDailyOrder` queries `where.OR = [{ branchId }, { branchId: null }]`.
  - **10:00 AM Fallback**: If by 10:00 AM the queue is not manually arranged, backend `getDailyOrder()` and frontend `MorningQueueProvider` automatically seed and follow yesterday's queue rotation, unblock floor starts/checkout, and display an alert banner to the Front Desk (`Notice to Front Desk: Daily queue was not manually arranged by 10:00 AM. System is using yesterday's queue rotation.`).

## 4. Post-Midnight Shift Operation & Gantt 2-Day Span
- **Problem**: Baan Iyara operating hours are **09:00 to 03:00** (cutoff 04:00 AM). Bookings created for 01:00 AM tonight (e.g. `#MQ5U09` and Andy Lee `#-H3Q6L`) were stamped with tomorrow's calendar date (`2026-10-20`) and hidden from Today's Live Matrix view.
- **Fixes**:
  - `booking-form.tsx`: Clamped validation so times between `00:00` and `03:59` AM evaluate as tonight (hours 24..27) rather than earlier today, allowing operators to select `Today` without errors. Target calendar date advances +1 while `businessDate` remains locked to today's shift (`2026-10-19`).
  - `live-matrix.service.ts`: Corrected `dayStart` (+07:00) and `minToSlot` (+7h); expanded `bookingsQuery` and `assignmentRecords` to include `nextDate` items falling within `[dayStart, dayEnd]` (09:00 to 03:00).
  - Updated `#MQ5U09` and `GRP-MVEUSSF4-H3Q6L` to `businessDate = '2026-10-19'` and `preferredTime = '2026-10-19 18:00:00 UTC'` (01:00 AM on 20 Oct Thailand time).
  - Gantt date header reflects the 2-day span: `19 - 20 Oct 2026`.
  - Gantt operational day uses a 04:00 AM cutoff so after 23:59 the view remains on the active shift.

## 7. System-Wide SST Removal (Thailand Zero Tax Scheme)
- **Problem**: In Thailand there is no Malaysian Sales & Service Tax (SST 8%). Legacy system code was dividing package prices by 1.08, displaying artificial "Net Ex-Tax" and "SST 8%" lines, grossing up packages in catalog, and printing Malaysian tax schedules in reporting.
- **Fixes**:
  - Set `SST_RATE = 0` system-wide (`pos/constants.ts` and `payments.service.ts`).
  - Package catalog prices are clean gross values: `toNetCents(gross) = gross`, `unitPriceCents = grossPriceCents`.
  - Removed all `SST 8%` lines and breakdowns across POS checkout, cart summary, thermal print templates, `ReceiptPreviewModal`, `ReceiptView`, `payments-modal.tsx`, `receipt-email.ts`, and `receipt-pdf.ts`.
  - Removed Malaysian Customs SST-02 statutory reporting schedules from `reporting/page.tsx` and `reports.service.ts`, replacing with clean Revenue Intake Breakdown.
  - Removed SST metric and table column from `official-daily-report-modal.tsx` and `sql-accounting-modal.tsx`.
  - Updated unit test suites `multi-guest-smoke.test.mjs`, `payments-transactional.test.mjs`, `vip-sst-exemption.test.mjs`, and `email-money-format.test.mjs` for 0 tax.
