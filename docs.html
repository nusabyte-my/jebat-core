⚠️ Set JEBAT_API_KEY before exposing the API. With the variable unset the server runs in development mode and leaves /api/* open. Keys are compared by SHA-256 digest, never stored in plaintext.

VPS Production

Two deployment routes exist. Pick one — running both against the same host will fight over the working tree.

Route A — GitHub webhook auto-deploy

A listener runs on the public host and pulls on every push to main. It updates the git checkout, copies the site pages and assets/ into the nginx web root, rsyncs only the changed files to the API host, restarts the PM2 processes and polls /health before reporting success.

# One-time setup, run as root on the target host
sudo bash infra/deploy/setup-webhook-deploy.sh --secret your-webhook-secret

Then add a repository webhook pointing at https://your-host/deploy-webhook with the same secret. The listener writes to /etc/systemd/system/jebat-deploy-webhook.service and logs to journald.

Route B — GitHub Actions CI/CD

.github/workflows/ci-cd.yml runs unit tests, integration tests, coverage, lint and build, then deploys via SSH: staging first, production on push to main only.

# Required repository secret
VPS_SSH_PRIVATE_KEY   # private key whose public half is on both hosts

Manual / first-time host setup

apt install -y python3.12 python3-pip git nginx

Air-Gapped Deployment

JEBAT runs with no external network calls. Inference stays local, memory stays on your disk, and telemetry is disabled by default.

With Ollama

# 1. Install Ollama offline (transfer the bundle via USB / internal mirror)
ollama serve &

# 2. Pull models on a connected machine, then copy the blobs directory across
ollama pull qwen2.5-coder:7b

# 3. Point JEBAT at it
JEBAT_LLM_PROVIDER=ollama
JEBAT_LLM_MODEL=qwen2.5-coder:7b
OLLAMA_HOST=http://127.0.0.1:11434

jebat

With llama.cpp (GGUF)

# 1. Serve a quantised checkpoint over the OpenAI-compatible API
llama-server --model qwen2.5-coder-7b.Q8_0.gguf --host 0.0.0.0 --port 8081

# 2. Point JEBAT at it
JEBAT_LLM_PROVIDER=local
LLAMA_CPP_HOST=http://127.0.0.1:8081

Split model / API hosts

For production, run inference on a GPU box and keep the API on a smaller host. Bind the model server to the internal interface only and firewall it to the API host.

# Model host (e.g. 10.0.0.20)
llama-server --host 10.0.0.20 --port 8081 --model model.gguf

# API host (e.g. 10.0.0.10)
LLAMA_CPP_HOST=http://10.0.0.20:8081
JEBAT_LLM_PROVIDER=local
ℹ️ Offline install: run the bootstrap with --no-inference to skip the Ollama / llama.cpp provisioning when your model servers are already stood up.

How failover works

  1. The request goes to the primary provider.
  2. On timeout, rate limit or auth failure, JEBAT walks JEBAT_LLM_FALLBACKS in order.
  3. The chain ends when a provider succeeds or the list is exhausted.
  4. The provider that answered is reported in the response metadata.
# ~/.jebat/config.yaml
llm:
  provider: ollama
  model: qwen2.5-coder:7b
  temperature: 0.2
  max_tokens: 4096
  fallbacks:
    - local
    - openai

Memory System

JEBAT keeps a six-type memory model with decay and consolidation. Traces persist as JSON under ~/.jebat/memory; vector retrieval is handled by Ghost DB when a database is configured.

Memory types

These are the six MemoryType values in the code — the enum is the source of truth.

TypeHoldsRetention
workingLive goals, facts and constraints for the current taskCurrent session
episodicEvents and agent runs, timestampedDecays over time
semanticDurable facts, decisions, knowledgePermanent
proceduralHow-to patterns, skills, files touchedPermanent
emotionalAffective valence, user preferences and frictionReinforced
prospectivePlanned intentions and follow-upsUntil executed

Behaviour

FeatureDescription
Forgetting curveEbbinghaus-style decay, reinforced on recall and on consolidation
autoMimpi dream cycleScheduled consolidation pass — scores traces, prunes noise, extracts patterns
Self-learningRecords failures and skill usage, then adapts behaviour per project
Vector retrievalGhost DB collection with HNSW indexing and cosine distance
Atomic persistenceWrites go to a temp file then rename, so a crash cannot truncate the store

Consolidation on a schedule

# Run the dream cycle manually
python -m jebat.cli.jebat_cli memory dream

# Or as a systemd timer (nightly). The interval is also configurable:
JEBAT_MEMORY_CONSOLIDATION_INTERVAL=3600
⚠️ Memory files are plaintext JSON. Do not store secrets in memory traces, and protect ~/.jebat/memory with filesystem permissions the same way you would a dotfile directory.

The ReAct loop

  1. Reason — analyse the task, decide the next action.
  2. Act — select and invoke a tool (file, terminal, web, …).
  3. Observe — read the tool result; large observations are folded head + tail rather than truncated at one end.
  4. Iterate — repeat until the task completes or the iteration budget is reached.

Reflexion gates

Before a step is accepted, the cognitive core can run domain gates — a build gate that parses the AST, a design gate that scores the UI across six axes, and a copy gate that rejects generic calls to action. Gates report what they checked; they do not publish a self-awarded score.

Delegating

# Route a task to the swarm
python -m jebat.cli.jebat_cli agent "Audit the auth module for vulnerabilities"

# Multi-agent delegation
python -m jebat.cli.jebat_cli delegate "Plan and implement the export feature"

Security & RBAC

Every tool carries a safety annotation, and the server classifies execution into three tiers before a call runs.

Execution tiers

TierMeaningApprovalCount (of 118)
READ-ONLYNo side effectsNone31
CONFIRMWrites or mutates stateUser confirmation74
DESTRUCTIVEIrreversibleExplicit approval + audit13

Counts are the MCP annotations the server emits (readOnlyHint / destructiveHint). The internal safety_tier registry uses a coarser auto / confirm / dangerous split (90 / 24 / 4) for the same tools.

API authentication

# Set the key; every /api/* route then requires it
JEBAT_API_KEY=your-secret-key

# Send it any of three ways
curl -H "Authorization: Bearer $JEBAT_API_KEY" https://host/api/status
curl -H "X-API-Key: $JEBAT_API_KEY" https://host/api/status
curl "https://host/api/status?api_key=$JEBAT_API_KEY"

Key lifecycle

POST /api/auth/rotate-key     # new key, grace period for the old one
GET  /api/auth/key-info       # inspect the calling key
POST /api/auth/revoke-key     # immediate kill

Hardening checklist

  • Set JEBAT_API_KEY. Unset means /api/* is open.
  • Bind the API and model servers to 127.0.0.1 or an internal interface; the compose stack already publishes to loopback only.
  • Set JEBAT_CORS_ORIGINS explicitly. The default allows the local WebUI; production must list trusted origins.
  • Proxy /api/pentest/* to 404 at the edge, as the shipped nginx template does.
  • Cap request bodies with JEBAT_MAX_API_BODY_BYTES (default 1 MiB).
  • Keep /docs and /openapi.json off public interfaces if you rely on route secrecy.
  • Treat ~/.jebat/memory as a secret — traces are plaintext JSON.
⚠️ Localhost is not safe by default. A server bound to 0.0.0.0 without JEBAT_API_KEY exposes destructive tools to the network. Set the key before publishing.

Request flow

User request
  → context assembly        (token budget)
  → adaptive compaction     (importance retention)
  → working memory inject   (goals / facts / constraints)
  → provider routing        (8 adapters, failover chain)
  → ReAct loop              (tool calls, safety-tier gated)
  → memory encode           (outcomes persisted)
  → cost record             (per iteration)
  → response                (SSE stream or JSON)

CLI Commands

⚠️ Two CLI surfaces — know which one you are on. The installed jebat command is the interactive agent REPL with a small command set. The wider operational command set lives in a separate module and is invoked as python -m jebat.cli.jebat_cli <command>. Both are shipped; they are not the same parser.

Installed jebat — agent REPL

Entry point jebat_cli_new.jebat:main. Four subcommands; anything else is treated as a prompt.

jebat                          # interactive REPL (default)
jebat code "Fix the bug"       # one-shot coding agent with tools
jebat chat "What is Python?"   # chat mode, no tools
jebat provider list            # list configured providers
jebat provider add             # connect a provider (wizard)
jebat provider test            # probe every provider
jebat provider use X           # switch the active provider

# Flags
jebat -c                       # resume the last session
jebat -s <ID>                  # resume a specific session

Skills (TokGuru)

Skills are markdown procedure files with optional scripts, discovered from ~/.jebat/tokguru/ (override with JEBAT_SKILLS_DIR).

python -m jebat.cli.jebat_cli skills list

# Or through the MCP tool
skill_manage(action="list")

A vendored example ships in skills/page-mascot/ — it draws cursor-tracking sprite-sheet mascots and wires them into a page.

Troubleshooting

Port already in use

lsof -i :8000          # macOS / Linux
netstat -ano | findstr :8000   # Windows
kill <PID>

# Or move the port
uvicorn main:app --port 8001

Ollama connection refused

ollama serve &
curl http://127.0.0.1:11434/api/tags   # should list models

If Ollama runs on another host, set OLLAMA_HOST to that address and confirm the firewall allows it. Ollama binds to loopback by default.

llama.cpp timeouts on first request

The model loads on first inference, which can take 60–90 s on a loaded box. Warm the server before sending traffic, and give health probes a deadline rather than a single attempt.

Database connection failed

JEBAT runs degraded without Postgres or Redis — this is not fatal. To enable:

JEBAT_DATABASE_ENABLED=true
DATABASE_URL=postgresql://jebat:password@localhost:5432/jebat_db
JEBAT_REDIS_ENABLED=true
REDIS_URL=redis://localhost:6379

401 unauthorized on /api/*

JEBAT_API_KEY is set, so every /api/* route needs it. Send it via Authorization: Bearer, X-API-Key, or ?api_key=. Unsetting the variable returns to open dev mode.

ModuleNotFoundError after pulling

# Reinstall the editable package so entry points refresh
pip install -e .

# Or run from the project root with the repo on the path
export PYTHONPATH="$PWD:$PYTHONPATH"
python -c "import jebat; print(jebat.__version__)"

Windows: bash not found from the installer

The bootstrap and the npm launcher both shell out to bash. Install Git for Windows (adds bash to PATH) or run inside WSL.

MCP client shows no tools

  • Confirm the server started: python jebat-mcp should print a startup banner on stderr.
  • Check the protocol revision — the server speaks 2026-07-28 and accepts three older revisions; an unrecognised one silently falls back to the default.
  • If pagination is on (JEBAT_MCP_TOOLS_PAGE), you are seeing one page. Follow nextCursor.
