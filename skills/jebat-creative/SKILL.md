# JEBAT Creative — Premium Product Interfaces

Build interfaces that could only belong to this product, audience, and task. **No default visual recipe.** Start from the work, not decoration.

## Non-negotiable direction

- Choose a product-specific macrostructure and one justified signature interaction.
- Use the nine references as **interaction research**, never a nine-brand collage or pixel copy.
- Preserve existing `DESIGN.md`, tokens, framework, accessibility, and component conventions.
- Do not force gradients, glass, three-card rows, pricing tiers, terminals, sparkles, dark themes, or Space Grotesk.
- No fake product screenshots, metrics, testimonials, activity, AI output, logos, or customer claims.
- No decorative section numbers, generic eyebrow labels, italic display type, or invented content.

## Design flow

1. **Preflight.** Read the existing system before changing UI. Record framework, fonts, semantic tokens, component library, motion, breakpoints, and target files.
2. **Task model.** State user, job, core artifact, primary action, failure recovery, and what must remain visible during work.
3. **Structure.** Select a domain grammar from [product-grammar.md](references/product-grammar.md), or justify a new one. Landing-page structure must differ from application structure.
4. **Direction.** Define a compact semantic token system and one signature element. Explain why both fit the subject. Boldness belongs in one place.
5. **Copy.** Use customer-facing verbs and real product behavior. One primary CTA per surface. No generic `Learn more`, `Get started`, or `Submit`.
6. **Build.** Match project conventions. Reuse components before creating new ones. Use semantic tokens, not mid-render palette/font improvisation.
7. **Prove.** Exercise the real surface at 320/375/414/768px and desktop. Check keyboard, focus, reduced motion, loading/error/empty/success, and no horizontal overflow.
8. **Critique.** Run [quality-gates.md](references/quality-gates.md). Fix any failed gate before claiming completion.

## Domain routing

| Product task | Structural starting point |
|---|---|
| Image/video generation | Studio canvas, model-aware settings, generation history, compare/inspect |
| Voice cloning/dubbing | Script ↔ cast ↔ timeline; waveform and playback are primary |
| SEO/analytics | Question → evidence → prioritized action; dense tables with readable metrics |
| Knowledge/workspace | Document canvas + semantic navigation; content over dashboard chrome |
| Dictation | Minimal voice presence → transcript → edit/export; privacy state visible |
| Projects | Work hierarchy + schedule/state; support planning, not generic KPI cards |
| Scheduling | Availability, time zone, conflict resolution, booking state |
| Support | Conversation list + customer context + response composer; triage first |
| Recording | Capture setup → recording state → trim/share; preview is the artifact |

Full research and repository provenance: [product-grammar.md](references/product-grammar.md).

## Premium quality floor

- **Purpose:** every region answers a user question or supports an action.
- **Hierarchy:** one dominant task; secondary controls recede without becoming inaccessible.
- **Specificity:** copy, states, density, and visuals reflect the actual product domain.
- **Typography:** deliberate display/body/utility roles; readable long content and tabular numbers for measurements.
- **Color:** semantic and restrained; one accent does not have to carry every status.
- **Depth:** borders, spacing, and layering communicate structure; shadows are not the default grouping mechanism.
- **Motion:** explain capture, playback, transitions, progress, or causality. Respect reduced motion.
- **Accessibility:** semantic HTML, visible focus, contrast, touch targets, keyboard operation, screen-reader names, and honest disabled/loading states.

## Output contract

Before implementation, provide:

- **Task:** user and primary job
- **Structure:** chosen domain grammar and why
- **Signature:** one memorable interaction or composition
- **System:** tokens/components preserved or introduced
- **Verification:** real surface and breakpoints to exercise

At handoff, report changed files, exercised behavior, visual verification, and remaining limitations. Never print self-awarded `P5 H5 E5 S5 R5 V5` scores as evidence. Quality claims need observed proof.
