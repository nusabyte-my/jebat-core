The model should not own your architecture.

Choose local inference or a configured cloud provider. Keep the same workspace, tool registry, and project knowledge instead of rebuilding your workflow around a vendor.

Technical details: tool safety tiers
IMPLEMENTATION: jebat/core/agent_loop.py
TierEnforcementExamplesUnlock
AUTO Executes immediately, no interaction. Every call still passes the allowlist filter and lands in the metrics ring. file reads · file_search · memory queries · git status/log · advisor_classify default
CONFIRM Pauses for interactive approval — prompt shows tool, tier, and truncated args. In the REPL, staged approval means one prompt per stage per session; file_write additionally renders a diff preview card. file_patch · git commit · docker · package installs · agent_execute answer Y, or a = always this session
DANGEROUS Hard-gated: pattern-matched on arguments (recursive deletes, disk writes, fork bombs) and rejected with a reason string. Unlocked by launching with elevated safety — --yolo or --safety dangerous puts the session in DANGEROUS mode and auto-approves every tier. rm -rf / · mkfs · dd to block devices · fork bombs · sudo rm --yolo or --safety dangerous at launch

Classification uses declared tiers and argument patterns; it is not a complete security sandbox. MCP CONFIRM/DANGEROUS calls return approval metadata without execution. Review elevated modes before enabling unattended writes.

UNDER THE HOOD

What actually happens on a tool call.

No magic — a deterministic pipeline. Every request your IDE sends walks the same six steps, and each one is observable in the metrics resource.

1IDE dispatch

Your client sends JSON-RPC over a local stdio process or configured HTTP transport. Authenticate remote access and restrict the server's network exposure.

2Allowlist + tier

JEBAT_MCP_TOOLS_ALLOW filters the registry; the tool's declared safety_tier decides the next move — auto, confirm, or refuse.

3Approval gate

confirm/dangerous calls return approval_required with the exact arguments — approve in the CLI, retry. Nothing executes silently.

4Deadline dispatch

A tool call has a declared timeout and structured errors. A timeout ends the wait; it cannot guarantee termination of an underlying OS process or thread.

5Progress + result

Long tools stream notifications/progress (agent loop iterations report fractional progress). Results cap at size limits; full output spills to jebat://artifact.

6Metrics recorded

Call count, error count, and latency land in per-tool rings — query live via resources/read: jebat://metrics/tools.

Agentix: solutions, not scripts

Scaffold with reflex (ReAct loop), flow (workspace-driven), or lattice (schema-typed tools) — three archetypes, one artifact format. Build into a SHA-stamped artifact. Eval it against golden tasks. Bounded by construction

Every run declares budget.tokens and budget.wall_clock. The ReAct loop stops and summarizes when either is hit; budgets below the 64-token-per-iteration floor are refused at spawn — fail fast, not mid-task.

Permissioned, not prompted

Tool allowlists (capped at 10 — enforced by agentix eval) and the workspace jail run in the harness before anything executes. Denied calls never touch the filesystem.

Keep a continuation record.

Completed runs retain a brief, manifest snapshot, tool-call log, and conversation. Resume a recorded run by ID. This is not a guarantee that an interrupted process saved every action.

Declared teams, explicit handoffs.

Three team manifests ship with the CLI. Legs share workspace files, declared artifact checks guard handoff, and human gates apply where configured. File existence is not a substitute for reviewing its contents.

MCP DEPLOY

Connect your IDE. Keep your workflow.

Use a local stdio process, a container, the npm launcher, or your authenticated HTTP endpoint. Tool availability depends on the installed capabilities and allowlist.

Try locally: install on this machine

Requires: Python 3.11+ with venv support, Git, curl, and Bash on Linux, macOS, or WSL. The installer downloads dependencies and may provision local inference; review the script before running it. Your IDE must be able to launch the installed jebat command.

Already installed: connect your IDE

Requires: JEBAT installed with Python 3.11+ on the IDE’s machine and an MCP-capable IDE. Print the configuration for your client with jebat mcp ide-config. This option does not install JEBAT or configure a model provider.

Run a configured container

Requires: Docker Engine with Compose, a JEBAT checkout, .env.production with a server API key, and the external network and data volume declared in the Compose file. Review the rendered configuration before starting services; keep the port private or put authenticated access behind TLS.

Try locally: use the npm launcher

Requires: Node.js 18+ with npm/npx and Python 3.11+. First use may download the installer and dependencies; review the package and meet the installer’s platform prerequisites before granting tool access. No repository clone is needed before invoking the launcher.

Use a server: connect to Remote HTTP

Requires: A running MCP endpoint over HTTPS, the server API key from your administrator, and an IDE that supports HTTP MCP. No local Python installation is needed for this connection. Use the authentication header your gateway requires—Authorization: Bearer or X-API-Key—and restrict server access. Never paste real keys into shared examples.

MODEL ROUTING

Providers are a routing table, not an architecture decision.

Every provider implements one interface; the router tries them in priority order and your tools, memory, and approvals are untouched by the switch.

Technical details: model routing and context budgets

Failover chain

generate_with_failover() walks providers in configured order. Local llama.cpp answers first; cloud keys only fire when you let them — and per-route policy gates apply to either.

Adaptive context budget

Input is budgeted against the model's real context window (input_token_budget()) — prompts are truncated to tokens, not characters, so a 4k local model and a 128k cloud model both get valid input.

Your existing model gateway

Use a supported provider or compatible API endpoint. Verify authentication, available model IDs, and context limits before starting a run.

Per-call cost visibility

Token usage is recorded per provider and per call (token_usage.py) — the WebUI surfaces spend, and local routes report cost as unmetered instead of hiding it.

RETRIEVAL

How a memory query actually resolves.

Implemented in EnhancedMemorySystem.retrieve() — every filter, weight, and fallback below is in the shipped code, not aspirational.

Technical details: memory retrieval, scoring, and decay
QUERY PIPELINE
1
Filter, before scoring

Candidates must pass every gate first: memory type, minimum strength, tag intersection, context match, time range. Cheap filters run before any embedding work.

2
Optional vector retrieval

When embeddings and the Ghost client are configured, retrieval can rank vector matches. Otherwise it uses local text similarity; neither path proves that a recalled fact is still correct.

3
Weighted score

Vector path: similarity×0.6 + strength×0.3 + activation×0.1. N-gram path: strength×0.6 + activation×0.3 + similarity×0.1 — recency and usage dominate when embeddings are unavailable.

4
Linked traces ride along

Results pull their linked traces (include_linked) so a decision arrives with its evidence — one query, full context chain.

5
Bounded injection

Recalled context enters the prompt under the same token budget as your task. Memory enriches; it never crowds out.

STRENGTH: EBBINGHAUS, NOT COUNTS
strength(t) = strength₀ · e−decay·Δt · (1 + reinforcement·0.5) reinforcement = min(1, access_count·0.1 + consolidation_count·0.2)

Memory strength changes with access, consolidation, and time. Retrieval can filter weak traces. This is a retention heuristic—not verification that a statement is true.

FAQ

Asked before you ask.

What is JEBAT and how does it fit into my stack?

JEBAT is a self-hosted agent runtime and MCP tool server. Use its CLI or connect an IDE, configure your providers, and retain project memory on your infrastructure. Registered tool tiers govern actions; elevated modes must be configured deliberately.

Does the learning advisor call a model?

No. It analyzes recorded project evidence deterministically and cites supporting memory IDs and timestamps. Advice and your feedback are stored in SQLite. Retention is not presented as measured task competence.

What does AutoMimpi change?

It consolidates selected project traces, extracts patterns and generalizations, and prunes weak memories. It respects a cooldown unless forced. A partial result means consolidation committed but a report or mirror failed to persist; inspect that error before retrying.

Can I reuse an existing MCP configuration?

Yes. jebat config import supports omp, opencode, and Claude configuration formats. Preview with --dry-run; existing entries are skipped unless overwrite is explicitly selected.

Can I operate without cloud models?

Yes, after installing dependencies and local model files. Choose a local provider and disable network-dependent integrations. Verify outbound traffic and credential settings before treating a deployment as air-gapped.

Do I need agent teams to use the learning tools?

No. Learning analysis, advice, and KB search do not spawn agents. Agentix teams are an optional, explicit execution path with declared members, budgets, and configured human gates.
